# Формат транскрипции 1.0

Один UTF-8 MD на аудиофайл: `<путь аудио>` → `Text/<путь аудио>.md`,
например `Recordings/заметка.wav` → `Text/Recordings/заметка.wav.md`.
Сохранять полный путь и расширение. Обратный путь — убрать `Text/` и последнее `.md`;
не допускать выхода за архив через `..` или симлинки. Путь определяет пару,
SHA-256 — побайтовое содержимое; копии имеют один хеш, изменение байтов меняет хеш.
Поле `audio` хранит относительный путь исходника в готовых файлах. Статусы обработки записываются в манифест.

Пример готового файла (хеш, модель и время заменить фактическими):

```markdown
---
schema_version: "1.0"
summary: "Обмен приветствиями; дальнейший разговор неразборчив."
spam_score: null
identification: partial
sha256: "<SHA-256 исходного аудио>"
duration_s: 300.00
model: "<модель>"
created_at: "2026-11-15T18:00:00+03:00"
tags: [жкх]
speakers:
  Иван: {person: ivanov_ivan, source: user, note: "Подтверждено пользователем."}
  Оператор: {person: null, temp: true, note: "Не представился."}
---

[00:00:01.23] **Иван** Алло, добрый день.
[00:00:03.90] **Оператор** Здравствуйте. [неразборчиво]
[00:00:05.10] **?** [шум]
```

Обязательны только `schema_version`, `sha256` (64 строчные hex-цифры),
`duration_s` (> 0), `model`, `created_at` (ISO 8601 с часовым поясом).
`summary` и `spam_score` присутствуют всегда; отсутствие сведений обозначается `null`.
При сохранении YAML используется `width=1000`, чтобы краткие `summary` и `note`
оставались в одну строку для поиска; явные переводы строк в значениях сохраняются.
`model` — фактический ID, если виден в журнале, иначе выбранное имя; не ответ модели.
Готовый MD появляется после проверки; ошибки остаются в отчёте работы.
Другие неизвестные необязательные поля опускать; пустые списки не требуются:

- `summary` — краткое содержание по-русски, не более 20 слов (разделённых пробелами):
  предмет, результат или договорённость, без выдуманных фактов и общих фраз.
  `null` — содержание пока не получено или не установлено.
- `spam_score` — конечное число 0–1 либо `null` (не оценено). Ноль — существующая
  оценка, а не отсутствие оценки. Это эвристическая оценка нежелательного спама/навязчивой
  рекламы, не калиброванная вероятность. Сам факт рекламы, работы робота или звонка
  организации не означает спам. `NaN`, Infinity, undefined и строки вместо чисел не допускаются.
- `duration_s` — секунды с двумя знаками (`300.00`, `12.34`); из исходных миллисекунд
  округлять к ближайшей сотой, половину вверх. Внутренние расчёты скрипта — в миллисекундах.
- `recorded_at`, `direction`, `contact`, `phones` — дата, направление
  (`in`/`out`), подпись контакта и телефоны из имени/аудио.
  Неизвестный пояс даты не подставлять, `mtime` исходника датой звонка не считать.
  При этом для самого MD-файла после сохранения и при миграциях
  выставляется файловый `mtime` по `recorded_at` (или дате из имени файла; для
  даты без пояса используется часовой пояс архива `+03:00`, для даты без времени —
  `00:00:00+03:00`; `ctime` не используется), чтобы каталог `Text/` сортировался
  в хронологическом порядке (массовая синхронизация: `scripts/sync_md_dates.py --apply`).
  Телефоны — строки; международный формат приводить только при однозначности,
  короткие номера сохранять. Контакт в имени, номер телефона и `.owner` папки считаются
  достаточными для установления личности, если разговор не указывает на другого пользователя телефона.
- `tags` — темы разговора русским snake_case: `семья`, `работа`, `финансы`,
  `медицина`, `жкх`, `поддержка`, `спам`; допустимы новые точные теги.
- `speakers` — участники записи и их связи с локальными справочниками `docs/people.yaml` и `docs/orgs.yaml`.
  Ключи в `speakers` — уникальные в пределах записи читаемые имена или роли (`Сергей`,
  `Смирнов Сергей`, `Оператор`, `Курьер`, `Голос 1`). Использовать `?` или `unknown` в ключах
  `speakers` запрещено. Неустановленный человек получает `person: null`; для одноразовых
  случайных собеседников (курьер, оператор, робот) допускается `temp: true` (признак
  временности, постоянная карточка не требуется).
  Поле `person` — ключ из `people.yaml` или `null`, `org` — ключ из `orgs.yaml`.
  `source: filename` — установлено по имени файла/номеру или `.owner` папки (если речь не указывает на другого пользователя телефона), `speech`/`user` — установлено по
  аудио/подтверждено пользователем; `note` — краткое основание или причина неуспеха.
  При совпадении имён ключ уточняется (например, `Сергей` и `Смирнов Сергей`).
  Можно дополнительно указать `role`: `owner`, `caller`, `callee`, `operator`, `robot`.
  Упоминание человека и принадлежность канала не делают его говорящим.
  В телефонном звонке, где слышен только робот/автоответчик, известный владелец аппарата
  из ближайшего `.owner` с `type: phone` также учитывается как участник:
  `person: <owner>`, `role: owner`, `source: filename`,
  `note: Владелец телефона; без слышимых реплик`. Реплики от его имени не добавляются.
  Контакт, на чей номер звонили, не становится личностью робота. При отсутствии речи
  сохраняются пустой `speakers` и `identification: not_applicable`.
- `reviewed_at` — дата полной человеческой проверки; краткое индексируемое содержание
  находится в YAML `summary`, а реплики идут сразу после `---` (без заголовков `## Речь`,
  `## Кратко`, `## Заметки`).

## Идентификация участников

`identification` — вычисляемый статус, отдельно от успешности транскрипции и тегов:
учитываются и голоса, и известный молчащий владелец телефона при ответе только робота.

| Значение | Смысл |
|---|---|
| `unresolved` | Ни один участник не установлен |
| `partial` | Установлена только часть участников |
| `complete` | Все участники установлены |
| `not_applicable` | В записи нет речи |

Для непривязанных голосов модель указывает предельно краткую `note` (3–6 слов в одну строку:
`Не представился`, `Автоответчик, оператор не назван`, `Нет фамилии`). При уже указанных
`person` или `org` (для робота) поле `note` необязательно и опускается, если привязка очевидна
по `source`. Услышанное имя без карточки остаётся в ключе или `label`.
Подтверждённая привязка — существующий `person` (кроме `null`) с `source: speech`, `user` или `filename`
(контакт/номер в имени файла и владелец телефона из `.owner` папки достаточны, пока по разговору
неочевидно, что телефоном пользуется другой человек);
для робота допустим `org` с `role: robot` и `source: speech` / `user` / `filename`. При распознавании
нового постоянного контакта с именем в метаданных файла или речи допускается
автоматическое создание новой карточки по ГОСТ 7.79-2000 (`<фамилия>_<имя>` или
`<имя>_<описание>`) без выдумывания фамилии. Организация человеческого
оператора не устанавливает его личность. При противоречии в речи `person` из `filename`/папки не привязывать.

Статус описывает сохранённые сведения, а не гарантирует правильность модели
и не заменяет человеческую проверку. Имеющиеся привязки полезны независимо от общего статуса.

Миграция старых MD вычисляет статус только по метаданным и меткам голосов,
без прослушивания и вызовов модели.
Для поиска неустановленных: `rg -l '^identification: (unresolved|partial)$' Text/`.

Реплика: `[HH:MM:SS.cc] **<Говорящий>** текст` (или `**?**`, без двоеточия; `cc` — сотые доли секунды, 2 цифры); время начала
реплики от начала оригинала, часы могут превышать 23. Длительность брать из `ffprobe` (`format.duration`).
0 ≤ время ≤ длительность (допускается превышение до 1000 мс из-за округления — при проверке
подрезать к длительности); порядок по времени (неубывающий), перекрытия отмечаются маркером `[одновременно]`.
Два знака задают формат, а не доказанную точность: `.20` допустимо, если более точная
граница не установлена. Не выдумывать последнюю цифру. Существующие таймкоды при
конвертации метаданных не исправлять; точность проверяется отдельно по аудио.
Различимые голоса всегда имеют свои читаемые ключи; `**?**` — только для отдельной реплики, где невозможно определить говорящего.
Правило едино для звонков, диктофона и голосовых сообщений: один голос — только один ключ говорящего.
Число участников и личность автора не выводить из папки. Сохранять язык оригинала;
поле `language` не заполнять догадкой. Дата без времени остаётся датой, без вымышленной полуночи.
Сохранять существенные повторы, оговорки и отрицания, добавлять пунктуацию;
бессодержательные «э-э» можно опускать. Маркеры: `[неразборчиво]`, `[возможно: …]`,
`[одновременно]`, `[смех]`, `[шум]`. Для тишины — пояснение без вымышленных реплик.

## Люди, организации и поиск

Транслитерация ID везде: **ГОСТ 7.79-2000 (система Б)**, только `[a-z0-9_]`, нижний регистр.

В `people.yaml` обязательны `schema_version`, словарь `people` и `name`:

```yaml
schema_version: "1.0"
people:
  ivanov_ivan:
    name: "Иван Иванов"
    notes: "Клиент по обслуживанию серверов, компания «Пример»."
    tags: [client]
    phones: ["+70000000110"]
    aliases: ["Иван Иванович"]
```

Это вымышленный пример. ID — `фамилия_имя` (при совпадениях добавить отчество/суффикс);
ключ после создания не менять, неизвестную фамилию не угадывать.
`notes`, `tags`, `phones`, `aliases` необязательны. Теги человека: `family`, `friend`, `client`,
`ally` (коллега/соратник), `hplus`, `service`, `doctor`; допустимы новые точные теги.

Для компаний и служб (МТС, клиники, такси и т.п.) используется отдельный справочник `orgs.yaml`
(`schema_version: "1.0"`, словарь `orgs`): ID — краткое название транслитом (напр. `mts`, `avokado_salon`),
поля `name`, `notes`, `tags`, `phones`, `aliases`.

Поиск: имя/псевдоним/телефон → ключ в `people.yaml` или `orgs.yaml` → `speakers.*.person` / `org`.
В `source` фиксировать происхождение привязки (`speech`/`audio`, `filename`, `user`).

Версии формата MD и справочников независимы. Новые необязательные поля повышают
MINOR, несовместимые изменения — MAJOR; неподдерживаемую версию не перезаписывать.
После общей конвертации 2026-11-16 эта схема принята за исходную **1.0**:
`identification`, `identity_note`, `summary`, `spam_score`, `duration_s`.
Исторические версии до конвертации не определяют текущую схему только по номеру.
[Конвертер](../scripts/migrate_catalog_fields.py) принимает прежние 1.0/1.1/1.2,
добавляет поля, переводит длительность в секунды и обновляет манифест.
Исходные разделы, таймкоды и ручные правки сохраняются. Неизвестное содержание — `null`;
длинное старое описание сокращается только по явно подготовленной карте содержания,
а не обрезанием первых слов. [Учёт идентификации](../scripts/migrate_identification.py)
обновляет только её статус, сохраняя версию исходного MD.

`manifest.jsonl` хранит последнее состояние пары по пути `audio` с сохранением истории:
`done`, `skipped`, `refused`. После явно разрешённого удаления добавляется `deleted`
с причиной и `duplicate_of` — списком сохранённых побайтовых копий (пуст для нулевого файла).
Эта запись не разрешает другие удаления. Путь, который появился вновь, проверяется заново.
