# Diaryze

[English](README.md) · Русский

Превращает звонки и диктофонные записи в Markdown, по одному файлу на запись. В расшифровке есть реплики на языке записи с таймкодами, имена или роли говорящих, ссылки на людей и организации и краткое содержание по-русски. [Формат 1.0](docs/formats.md)

## Установка и запуск

Нужны Python 3.11+ и [FFmpeg](https://ffmpeg.org/download.html) (`ffmpeg` и `ffprobe` в `PATH`). На macOS установите его через `brew install ffmpeg`. Установите [Google Antigravity CLI](https://antigravity.google/docs/getting-started) и запустите `agy`, чтобы войти в аккаунт с доступом к нужным моделям. PyYAML ставится вместе с пакетом. [Необязательные инструменты восстановления](#восстановление-аудио)

```bash
cd "/путь/к/записям"
git clone https://github.com/sukamenev/diaryze.git
python3 -m venv diaryze/.venv
source diaryze/.venv/bin/activate
python -m pip install ./diaryze
diaryze --ui ru --dry-run
```

По умолчанию Git создаёт папку `diaryze`. Можно передать своё имя последним аргументом `git clone` и подставить его в пути выше. Оставьте `00_Diaryze_Data/` для данных архива. При поиске аудио Diaryze пропускает рабочую копию целиком.

Из корня архива попробуйте обработать несколько записей.

```bash
diaryze --ui ru --workers 2 --limit 5
```

По умолчанию Diaryze использует текущую папку как корень архива. Для запуска из другой папки задайте `diaryze --root "/путь/к/записям"`. Параметр `--folder Phone/2025` ограничивает расшифровку и подготовку кандидатов указанной папкой внутри архива. Если PyYAML уже установлен, `python3 /путь/к/diaryze/diaryze.py` принимает те же параметры.

Английский — язык интерфейса по умолчанию. Используйте `--ui ru` для русской справки, подсказок и сообщений о ходе работы. Параметр `--ui en` явно выбирает английский. Язык расшифровки и правила подготовки краткого содержания задаются отдельно.

Если чекаут уже лежит в другом месте, можно создать в архиве симлинк `diaryze` на него. С установленным PyYAML можно вызвать скрипт из корня архива:

```bash
python3 ./diaryze/diaryze.py --ui ru --folder Phone/2025 --dry-run
```

`--models model-a,model-b` задаёт всю цепочку. Укажите одно имя, чтобы использовать одну модель. `--model` задаёт первую модель с резервами из настроек. Короткие записи собираются в партии, длинные делятся с перекрытием и пересчётом таймкодов. При повторном запуске готовые MD с совпадающим хешем исходника пропускаются. Прерванная длинная запись продолжается с сохранённых частей: чекпоинт привязан к хешу аудио и макету нарезки и удаляется после публикации MD.

По опыту автора, **5 часов квоты Antigravity хватало на 18–26 часов разговоров**. Скорость зависит от моделей, записей, повторов и числа работников.

## Что хранится в архиве

- `00_Diaryze_Data/Text/` повторяет структуру исходников. Для `Phone/2025/звонок.m4a` получится `00_Diaryze_Data/Text/Phone/2025/звонок.m4a.md`.
- `00_Diaryze_Data/people.yaml` и `00_Diaryze_Data/orgs.yaml` содержат справочники. В `00_Diaryze_Data/manifest.jsonl` записывается история обработки.
- В `00_Diaryze_Data/voice_samples/<person>/<phone|recorder>/confirmed/YYYY-MM-DD_NN.flac` лежат подтверждённые образцы голоса, которые хранятся независимо от исходных звонков.
- В соседней папке `candidate/` лежат клипы для прослушивания и отбора.
- `00_Diaryze_Data/logs/` содержит диагностику, в том числе ответы модели.
- `00_Diaryze_Data/.work/checkpoints/` содержит принятые части длинных записей до публикации итогового MD.
- `00_Diaryze_Data/reports/` содержит отчёты по архиву и результаты сравнений моделей.

Существующие архивы могут продолжать использовать прежний каталог `Data/`. Справочники и манифесты в старом каталоге `docs/` также поддерживаются. Исходники остаются на месте. `agy` отправляет аудио и контекст распознавания поставщику модели.

## Идентификация говорящих

Справочники создаются при обработке. Чтобы заполнить их заранее, запустите `diaryze --root "/путь/к/записям" --init` и отредактируйте YAML. Существующие справочники сохраняются.

Пример карточки в `00_Diaryze_Data/people.yaml`.

```yaml
schema_version: "1.0"
people:
  ivanov_ivan:
    name: Иван Иванов
    aliases: [Ваня]
    tags: [owner]
```

В файле `.owner` укажите в поле `owner` ID владельца телефона из `people.yaml`. Для каждой папки звонков действует ближайший `.owner`.

```yaml
type: phone
owner: ivanov_ivan
label: Иван
```

Diaryze сопоставляет контакт из имени файла со справочниками и сведениями из речи. При достаточных основаниях добавляет карточку после сверки с известными именами и номерами. Проверяйте автоматические привязки и сохраняйте ID, на которые ссылаются MD. У неизвестных голосов остаётся `person: null`. Разовых собеседников можно пометить `temp: true` без карточки.

### Образцы голоса владельцев телефонов

При первом запуске в папках без эталона владельца Diaryze сопоставляет короткие звонки с разными контактами из выбранной папки и вырезает до трёх кандидатов на папку с `.owner`. Сам файл `.owner` может лежать выше выбранной папки, вплоть до корня архива. Скрипт останавливается перед расшифровкой и выводит пути к файлам в `00_Diaryze_Data/voice_samples/<person>/phone/candidate/` для прослушивания.

Кандидат может содержать от 5 до 20 секунд чистой речи одного человека. При сопоставимом качестве звука и уверенности в личности предпочтительны клипы от 10 секунд.
Отдельным запросом модель проверяет каждый вырезанный FLAC. Если слышен второй голос, Diaryze один раз пытается укоротить или сдвинуть клип, добавляя к окну поиска до пяти секунд исходника с каждой стороны. Исправленный клип проверяется повторно. В папку кандидатов попадают клипы, где проверка обнаружила ровно одного говорящего.

Прослушайте клипы в `candidate/` и перенесите лучший FLAC в соседнюю папку `confirmed/`. Оставьте соответствующий JSON в `candidate/`. Запуск до подтверждения снова покажет готовых кандидатов. После переноса Diaryze проверит клип, сохранит сведения о происхождении и продолжит расшифровку. Для каждого звонка он берёт один образец, ближайший по дате в любую сторону. При равных расстояниях предпочтение у телефонного образца. Для звонка без даты используется самый свежий датированный образец.

`--prepare-voice-sample` готовит кандидатов для владельца выбранной папки без запуска расшифровки. Можно явно передать ID владельца. `--approve-voice-sample "путь/к/2025-03-14_01.flac"` подтверждает клип, а `--reject-voice-sample "путь/к/2025-03-14_01.flac"` отклоняет его набор.

Если клипы готовы, команда выводит инструкцию по прослушиванию и подтверждению. При сбое она показывает короткую ошибку и путь к журналу. В `00_Diaryze_Data/logs/` сохраняются пути к исходникам, статус чтения каждого звонка и полные ответы модели при подборе, проверке и исправлении клипов.

`--no-voice-samples` запускает расшифровку без подготовки и использования образцов. `--skip-voice-sample-preflight` запускает расшифровку сразу и использует утверждённые образцы, если они есть.

## Восстановление аудио

Diaryze работает с временными копиями. FFmpeg перепаковывает первую читаемую аудиодорожку, а если это не удаётся, пробует декодировать её в WAV. Для повреждённого контейнера AAC, например M4A без `moov`, скрипт сначала пытается извлечь уцелевшие кадры через [FAAD2](https://github.com/knik0/faad2) и перепаковать их через FFmpeg. Библиотека ставится через `brew install faad2` на macOS или `sudo apt install libfaad2` в [Debian](https://packages.debian.org/trixie/libfaad2).

Если извлечение не помогло, Diaryze пробует `untrunc` из `PATH` с поддержкой `-dst` и исправным M4A или MP4 из той же папки. Лучше взять эталон с того же устройства и с теми же настройками. У проекта есть инструкции по сборке и ручному запуску через Docker. [untrunc](https://github.com/anthwlock/untrunc#building)

Восстановленное аудио и подготовленная дорожка проходят полное строгое декодирование перед распознаванием. Если сервис всё же отклоняет медиа как пустое или повреждённое, Diaryze записывает `needs_recovery`, прекращая перебор моделей для этих байтов. При такой ошибке в пакете записи проверяются по одной, чтобы исправные файлы могли завершиться.

Если файл остался нечитаемым, Diaryze его пропускает и записывает `needs_recovery` с причиной и хешем исходника. Пустые файлы и файлы без аудиодорожки получают `skipped`. После установки инструментов команда `diaryze --retry-recovery` вернёт в очередь файлы с новой отметкой и старые пропуски из-за повреждения. Если байты файла с `needs_recovery` изменятся, он вернётся в обычную очередь. Ключи `--no-faad` и `--no-untrunc` отключают соответствующие методы.

## Поиск и обслуживание архива

Запускайте вспомогательные скрипты из папки архива по их пути в клоне. [find.py](scripts/find.py) ищет по репликам и краткому содержанию, фильтрует по людям, организациям, номерам, датам и длительности. Выводит таблицу, пути к MD или аудио либо JSONL. Корень архива можно задать через `--root`.

```bash
python3 /путь/к/diaryze/scripts/find.py --text 'договор|оплат[ауы]' --limit 20
python3 /путь/к/diaryze/scripts/find.py --person ivanov_ivan --from 2025-01-01
python3 /путь/к/diaryze/scripts/find.py --root "/путь/к/записям" --folder Phone/2025 --direction in --format paths
```

| Скрипт | Назначение |
| --- | --- |
| [find_audio_duplicates.py](scripts/find_audio_duplicates.py) | Отчёт о побайтовых копиях аудио. |
| [audit_recording_dates.py](scripts/audit_recording_dates.py) | Сверка дат по именам, метаданным и времени изменения. Для изменения дат аудио нужны план и `--apply`. |
| [sync_md_dates.py](scripts/sync_md_dates.py) | Сверка времени изменения MD с датой записи. Ключ `--apply` синхронизирует даты. |
| [swap_speakers.py](scripts/swap_speakers.py) | Меняет местами метки двух говорящих в репликах одного MD. Аргументы `"00_Diaryze_Data/Text/запись.m4a.md" "Анна" "Иван"` показывают, сколько реплик сменит метку. Ключ `--apply` сохраняет правку. |
| [relink_catalog_speakers.py](scripts/relink_catalog_speakers.py) | Поиск карточек для непривязанных голосов. |
| [migrate_identification.py](scripts/migrate_identification.py), [migrate_phone_owners.py](scripts/migrate_phone_owners.py), [migrate_catalog_fields.py](scripts/migrate_catalog_fields.py) | Предпросмотр обновлений MD. Ключ `--apply` записывает их. |

Модели, настройки обработчиков, таймауты и пороги подбора образцов находятся в [config.py](scripts/diarizer/config.py), инструкции модели — в [prompts/](prompts/README.md). Временные скрипты можно хранить в `scripts/local/` внутри чекаута. Git игнорирует эту папку.

Из клона можно запустить `diaryze --selftest` для проверки доступных инструментов и `python3 -m unittest discover -s scripts/tests -q` для тестов с синтетическим аудио и подставными ответами моделей.
